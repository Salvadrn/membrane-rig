0:00→0:20 Title This summer I built an instrument that automates a membrane-permeability test. …and everything I show is verified in simulation — I'll come back to why that's deliberate.
0:20→1:15 Why it's hard The lab builds two-phase cooling devices — they boil liquid through a porous mesh wick. pore size = flow vs capillary pumping · k ≈ 10⁻¹³–10⁻¹² m² · meshes differ <10× → must be repeatable
1:15→2:10 Two errors Today it's done by hand: hold the pressure with a valve, time the collection with a stopwatch. ±3 kPa at 20 kPa = ±15%, and never recorded · hose transfer spills the same way = bias, not noise
2:10→3:05 The core idea Two different errors need two different fixes. timing → DELETE it, give the clock to the computer (solenoid on the same 20 Hz loop) · pressure → make it HONEST, analyze against the measured mean, not the setpoint · regression averages out scatter, it can never undo bias
3:05→4:05 Darcy = slope You don't need membranes to read this: flow is proportional to pressure. slope IS the permeability · R² is a free physics check (flag under 0.98) · slope not per-point average → a constant offset lands in the intercept · each dot = one 60 s collection
4:05→4:45 It checks itself Warm water is thinner, so it flows faster and the raw slope goes up. but k multiplies the slope by viscosity again → they cancel · k must NOT change with temperature · if it drifts, the instrument is broken, not the membrane
4:45→5:45 The system The existing vessel is left untouched — everything attaches around it. servo on the ball valve · PID at 20 Hz · divider → 16-bit ADC · probe for temperature · 3-way solenoid diverter · ~$300 · vessel never modified
5:45→6:55 Validation
— say “in simulation”		 These are all from simulation, running the exact production code against a modeled plant. ±8 kPa disturbance → held to 0.21–0.69 kPa · 15 °C sweep → k constant to 5 sig figs while raw slope moved 39% · reproduced a real hand-taken dataset: k 1.44e-12, pore 6.8 µm, R² 0.994
6:55→7:45 Trusted & honest A word on discipline — being verifiable without hardware was a design goal. every line ran end-to-end before a part was bought · plainly: NOTHING has run on hardware yet, the Pi boots but no cable is connected · next: commission and retune on the real rig
7:45→8:00 Take-away One error eliminated, the other made honest. that's the line between real automation and a Raspberry Pi bolted onto an experiment · thank TEMP Lab, ENLACE, Kwangsoo Cho, Prof. Renkun Chen
